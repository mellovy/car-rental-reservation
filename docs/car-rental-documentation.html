1. Overview

The Car Rental Management System is a ServiceNow scoped application that provides a customer-facing service portal for booking rental cars, and staff-facing desk/dashboard views for managing the fleet, the rental calendar, and reservations. It supports three kinds of bookers — logged-in patrons, anonymous guests, and reception staff (walk-ins) — and enforces a rental calendar with business days, holidays, and a per-day online booking cutoff.

Cutoff semantics: online (non-staff) bookings for a given day close at that day's cutoff time (15:00 default). Receptionists and admins may book past the cutoff (walk-ins at the desk). Holidays never accept bookings.

8. Security

  • Guest booking is intentionally allowed: reservation create ACLs include an empty-script allow and a script answer=true row; anonymous users book through the portal widgets (client_type=guest).
  • Basic auth is disabled instance-wide (glide.authenticate.basic_auth.restriction.active=true, restricted to snc_basic_auth_api_access) — REST API 401s for app users are platform policy, not an app defect. The portal widgets are the supported client path.
  • Read ACLs on car/cal_day are staff-only. This causes no user-visible breakage because portal widget GlideRecord reads bypass table read ACLs, and the complaint form uses a select box. If hardening is desired: elevate security_admin in the UI and add patron (or clear roles for public read) to those ACLs — ACL writes require interactive elevation and cannot be automated.
  • Patron data isolation: patrons see and act only on their own reservations (ownership checks in My Reservations; "Patrons may only cancel" rule server-side).
  • Passwords follow the instance password policy (no name-derived passwords); test-user passwords were set by the owner in the UI.

9. Demo guide

9.1 Guest books a car

  1. Open https://dev409824.service-now.com/carrental (logged out).
  2. Browse the fleet; filters and booked/maintenance pills are visible without login.
  3. Reserve → fill driver details + guest contact → confirm. Booking lands with state=reserved, client_type=guest; client + desk emails go out.

9.2 Patron cancels (72h rule)

  1. Log in as test.patron → My Reservations → Cancel booking.
  2. Cancelling within 72h of pick-up is rejected with the rule message; outside 72h it succeeds and triggers the cancellation email.

9.3 Receptionist walk-in (cutoff bypass)

  1. Log in as test.receptionist → land on Desk.
  2. Use "New reservation (walk-in)" — the cutoff time does not block desk bookings.
  3. Use Returned / Cancel on any active reservation.

9.4 Admin dashboard

  1. Log in as test.admin → land on Dashboard.
  2. Fleet table shows live status (On rent / Booked / Out of service / Out of service (dates)); calendar shows business days with cutoffs and holidays.
